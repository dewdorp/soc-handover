SOC 교대근무 인수인계 플랫폼 — 패치(앱만 교체) 안내
=====================================================

이미 설치된 PC 의 앱과 화면만 새 것으로 바꿉니다. Python · PostgreSQL · 데이터는
그대로 두므로 파일이 작고(수 MB) 1~2분이면 끝납니다.

대상: 이미 이 플랫폼이 설치된 PC (전체 설치 패키지로 한 번 설치한 뒤)


1. 패치하기
-----------
 1) zip 파일을 PC 로 복사한 뒤 압축을 풉니다.
    ※ 압축 파일 안에서 바로 실행하지 말고 반드시 "압축 풀기"를 먼저 하십시오.
 2) 푼 폴더의 UPDATE.cmd 를 더블클릭합니다.
    서비스 모드로 설치했다면 권한을 물어봅니다 → [예]
 3) 지금 버전과 새 버전을 보여 줍니다. Y 를 입력하면 진행합니다.
 4) "패치 완료"가 나오면 끝입니다. 브라우저는 새로고침(Ctrl+F5) 하십시오.

 설치 폴더를 못 찾으면 직접 알려 주십시오:
   UPDATE.cmd -InstallDir D:\SOC-Handover


2. 패치 프로그램이 하는 일
--------------------------
   1) 설치 폴더 확인 · 패치 파일 검사(MANIFEST.sha256 — 복사 중 깨졌는지)
   2) 라이브러리 목록이 그대로인지 확인
      → 바뀌었으면 여기서 멈추고 전체 패키지로 안내합니다(데이터는 그대로 유지됩니다)
   3) 앱 중지 (DB 는 켜 둡니다) → DB 백업 → 지금 파일을 rollback 폴더에 보관
   4) 앱 · 화면 · 운영 스크립트 · 문서 교체
   5) DB 구조 갱신(마이그레이션) → 앱 시작 → 응답 확인

 건드리지 않는 것: 설정(.env), 데이터(data), 첨부파일, 백업(backup), 로그(logs),
                   Python · PostgreSQL(runtime), 서비스 · 예약 작업 · 방화벽 등록

 다시 실행해도 안전합니다. 같은 버전을 다시 패치해도 문제 없습니다.


3. 잘못되면
-----------
 패치 중 실패하면 보관해 둔 파일로 **자동으로 되돌리고** 앱을 다시 띄웁니다.
 화면에 되돌린 결과와, 필요하면 DB 를 되돌릴 백업 파일 경로가 나옵니다.

 직접 되돌리려면
   1) stop.cmd 로 앱을 끕니다.
   2) 설치 폴더의 rollback\<이전버전>_<날짜시각>\ 안의 내용을 설치 폴더에 덮어씁니다.
   3) DB 도 되돌려야 하면 restore.cmd 로 패치 직전 백업(backup 폴더의 가장 최근 파일)을 복구합니다.
   4) start.cmd 로 다시 켭니다.

 기록(로그)
   - 패치 진행 기록: 화면 마지막 줄에 나오는 %TEMP%\soc-handover-update-<날짜시각>.log
   - 앱 기록       : 설치 폴더의 logs\ (service.log, uvicorn.err.log)


4. 전체 패키지를 써야 하는 경우
-------------------------------
 - Python 라이브러리가 바뀐 버전 (패치 프로그램이 확인하고 안내합니다)
 - PostgreSQL 버전이 올라간 경우
 - 처음 설치하는 PC

 두 경우 모두 전체 패키지(SOC-Handover-<버전>-offline.zip)의 INSTALL.cmd 를 실행하면
 업그레이드로 진행되며, 데이터 · 설정은 그대로 유지됩니다(교체 전 DB 백업).


자세한 운영 방법은 설치 폴더의 docs\OPERATIONS.md 를 보십시오.


[1.3.1 운영 편의성 패치 — 적용 전 필독]
=========================================

대상
  · 1.3.0 계열이 설치된 서버. 운영 DB 는 PostgreSQL 16 입니다.
  · 앱과 DB 구조가 함께 바뀌므로 업무가 적은 시간에 적용하십시오.
  · 운영 소스를 손으로 고친 적이 있으면 먼저 확인하십시오.


1. 이 패치가 자동으로 바꾸는 것 / 바꾸지 않는 것
------------------------------------------------
 바꾸는 것
   · 앱 · 화면 · 운영 스크립트 · 문서 파일
   · DB 구조: 운영 지식 표(문서 · 태그 · 개정 이력 · 인계 연결),
     정기 점검 완료 표, 전체 공개 전환 이력 표
   · 새로 쓰는 인수인계의 기본 공개 범위: 그룹을 고르지 않으면 '전체 공개'

 바꾸지 않는 것
   · **이미 쌓인 자료의 공개 범위** — 패치를 적용하는 것만으로 과거 자료가
     전체 공개가 되는 일은 없습니다.
   · 계정 · 인수인계 · 개인 메모 · 첨부 · 모든 이력 · 금고 암호화 키(VAULT_KEY)
   · 설정(.env) · 데이터 · 백업 · 로그 · Python · PostgreSQL · 서비스 등록
   · 기존 감사로그 (한 줄도 지우지 않습니다)


2. 적용 절차
------------
 1) 사용자에게 점검 시간을 알리고, 돌고 있는 Import/Export 가 없는지 확인합니다.
 2) backup.cmd 로 DB · 첨부 백업을 받습니다.
    VAULT_KEY 가 .env 에 있고 별도 보관본이 있는지도 확인하십시오
    (이 키가 없으면 보관된 비밀번호를 풀 수 없습니다).
 3) 위 1절 안내대로 압축을 풀고 UPDATE.cmd 를 실행합니다.
 4) 화면에 '파일 검사 → DB 백업 → 교체 → DB 구조 갱신 → 시작 → 응답 확인'이
    모두 나오는지 봅니다.
 5) 로그인해서 /settings · /knowledge · /credentials · /audit · /handovers 를 엽니다.
 6) 점검 스크립트를 한 번 돌립니다:
      runtime\python\python.exe scripts\verify_install.py http://localhost:8080 admin
 7) 당사 · 외주 · 특정 그룹만 가진 계정으로 각각 로그인해 인계 · 문서 · 금고의
    열람 경계를 확인하십시오(관리자 한 계정으로는 확인되지 않습니다).


3. 패치를 올린 뒤 관리자가 정해야 하는 것 네 가지
-------------------------------------------------
 (1) 과거 '그룹 미지정' 자료를 전체 공개로 바꿀 것인가
     · 그대로 두면 지금까지와 똑같이 보입니다. 바꾸려면
       관리자 → 열람 그룹 → '과거 그룹 미지정 자료 전체 공개 전환' 에서
       건수와 **공개될 자료 목록**을 확인하고, 경고를 읽고,
       확인 문구 '전체공개로 전환' 을 직접 입력하고, 백업 확인에 동의합니다.
     · 전환하면 **로그인한 모든 활성 계정**(외주 · 협력사 포함)이 읽습니다.
       과거 인계 본문에 계정 · 장비 · 고객 정보가 적혀 있을 수 있습니다.
     · 잘못 바꿨으면 같은 화면에서 묶음 단위로 되돌릴 수 있습니다.
     · 명시적으로 그룹을 지정한 자료는 전환 대상이 아니며 그대로 유지됩니다.

 (2) 비밀번호 일괄 열람 시간 — 설정 → 비밀번호
     · 열람 시간 기본 5분(1~10분), 연속 유지 상한 기본 15분(5~15분).
       15분은 보안 상한이라 더 길게 설정할 수 없습니다.

 (3) 감사로그 열람 기록을 켤 것인가 — 설정 → 감사로그
     · 기본은 꺼짐(단순 열람 성공만 기록하지 않습니다).
     · 로그인 실패 · 계정 잠금 · 권한 변경 · 내보내기 · 비밀번호 열람 ·
       설정 변경 · 백업/복구와 **막힌 열람**은 설정과 무관하게 계속 기록됩니다.

 (4) 정기 점검을 등록할 것인가 — 일정 → 새 일정
     · 종류를 '점검'으로, 반복을 매일/매주/매월로 등록하면
       대시보드 '오늘 점검'과 교대 마감 점검에 그 날 회차가 나옵니다.


4. 알아 두어야 할 범위
----------------------
 · 공용(SHARED) 금고 비밀번호는 지금도 `credential:read` 권한이 있는 모든
   사용자에게 보입니다. 1.3.1 은 이 범위를 **넓히지 않습니다** — 한 건씩
   보던 것을 목록으로 보여 주는 것뿐이고, 볼 수 있는 항목은 그대로입니다.
   외주 계정에 보이지 않게 해야 한다면 그 계정에 `credential:read` 권한을
   주지 않는 것이 가장 정확합니다(금고 그룹 접근통제 검토 결과는
   docs\SECURITY.md 10-3 에 있습니다).
 · 다른 사람의 개인(PERSONAL) 비밀번호는 일괄 열람에도 보이지 않습니다.
 · 운영 지식 문서의 첨부는 그 문서의 열람 권한을 그대로 따릅니다.

Windows 설치 PC 에 frontend\src 는 필요하지 않습니다 — 이미 빌드된
frontend\dist 를 패치가 교체합니다.
