SOC 교대근무 인수인계 플랫폼 — 패치(앱만 교체) 안내
=====================================================

이미 설치된 PC 의 앱과 화면만 새 것으로 바꿉니다. Python · PostgreSQL · 데이터는
그대로 두므로 파일이 작고(수 MB) 1~2분이면 끝납니다.

대상: 이미 이 플랫폼이 설치된 PC (전체 설치 패키지로 한 번 설치한 뒤)


1. 패치하기
-----------
 1) zip 파일을 PC 로 복사한 뒤 압축을 풉니다.
    ※ 압축 파일 안에서 바로 실행하지 말고 반드시 "압축 풀기"를 먼저 하십시오.
 2) 푼 폴더의 UPDATE.cmd 를 더블클릭합니다.
    서비스 모드로 설치했다면 권한을 물어봅니다 → [예]
 3) 지금 버전과 새 버전을 보여 줍니다. Y 를 입력하면 진행합니다.
 4) "패치 완료"가 나오면 끝입니다. 브라우저는 새로고침(Ctrl+F5) 하십시오.

 설치 폴더를 못 찾으면 직접 알려 주십시오:
   UPDATE.cmd -InstallDir D:\SOC-Handover


2. 패치 프로그램이 하는 일
--------------------------
   1) 설치 폴더 확인 · 패치 파일 검사(MANIFEST.sha256 — 복사 중 깨졌는지)
   2) 라이브러리 목록이 그대로인지 확인
      → 바뀌었으면 여기서 멈추고 전체 패키지로 안내합니다(데이터는 그대로 유지됩니다)
   3) 앱 중지 (DB 는 켜 둡니다) → DB 백업 → 지금 파일을 rollback 폴더에 보관
   4) 앱 · 화면 · 운영 스크립트 · 문서 교체
   5) DB 구조 갱신(마이그레이션) → 앱 시작 → 응답 확인

 건드리지 않는 것: 설정(.env), 데이터(data), 첨부파일, 백업(backup), 로그(logs),
                   Python · PostgreSQL(runtime), 서비스 · 예약 작업 · 방화벽 등록

 다시 실행해도 안전합니다. 같은 버전을 다시 패치해도 문제 없습니다.


3. 잘못되면
-----------
 패치 중 실패하면 보관해 둔 파일로 **자동으로 되돌리고** 앱을 다시 띄웁니다.
 화면에 되돌린 결과와, 필요하면 DB 를 되돌릴 백업 파일 경로가 나옵니다.

 직접 되돌리려면
   1) stop.cmd 로 앱을 끕니다.
   2) 설치 폴더의 rollback\<이전버전>_<날짜시각>\ 안의 내용을 설치 폴더에 덮어씁니다.
   3) DB 도 되돌려야 하면 restore.cmd 로 패치 직전 백업(backup 폴더의 가장 최근 파일)을 복구합니다.
   4) start.cmd 로 다시 켭니다.

 기록(로그)
   - 패치 진행 기록: 화면 마지막 줄에 나오는 %TEMP%\soc-handover-update-<날짜시각>.log
   - 앱 기록       : 설치 폴더의 logs\ (service.log, uvicorn.err.log)


4. 전체 패키지를 써야 하는 경우
-------------------------------
 - Python 라이브러리가 바뀐 버전 (패치 프로그램이 확인하고 안내합니다)
 - PostgreSQL 버전이 올라간 경우
 - 처음 설치하는 PC

 두 경우 모두 전체 패키지(SOC-Handover-<버전>-offline.zip)의 INSTALL.cmd 를 실행하면
 업그레이드로 진행되며, 데이터 · 설정은 그대로 유지됩니다(교체 전 DB 백업).


자세한 운영 방법은 설치 폴더의 docs\OPERATIONS.md 를 보십시오.



[1.3.1 운영 편의성 패치 — 적용 전 필독]
================================

설치 대상
  · 기존 SOC-Handover 1.3.0 계열을 사용 중인 서버
  · 운영 소스의 커스텀 변경이 없는지 먼저 확인하십시오.
  · Windows/SQL Server 아님: 운영 DB는 PostgreSQL 16입니다.
  · 1.3.1 앱·DB 구조 변경을 포함하므로 업무가 없는 시간에 적용하십시오.

주요 기능
  1. 운영·관리 → 설정: 날짜 설정/잘못된 형식 화면 오류 방어
  2. 감사로그: 일반 인수인계 보기 성공 기록 기본 중지. 기존 기록은 유지.
     화면에서는 기존 보기 기록을 기본으로 숨기고 원하면 표시 가능.
  3. 그룹 미지정 인수인계: 모든 로그인 사용자에게 공유.
     실제 그룹이 지정된 글은 해당 그룹 사용자만 읽도록 기존 정책 유지.
     기존 미분류 그룹만 있던 글도 전체 공개로 전환됨.
  4. 운영 지식 메뉴: SOC SOP/절차/분석/비상 대응/참고 자료 + 문서 업로드/분류/검색,
     공개 그룹 및 작성자 수정 권한/재검토 예정일
  5. 금고: 로그인 계정 비밀번호로 한 번 인증해 접근 가능한 현재 비밀번호를
     한 화면에 일시 표시. 기본 5분/5분 연장/연속 15분 상한/즉시 잠금.
     다른 사용자의 PERSONAL 암호는 여전히 숨김.
  6. 기존 1분 개별 열람 창 역시 기본 5분/5분 연장.

  경고: 공용(SHARED) 금고 비밀번호는 현재 기존 정책대로 모든 로그인
  사용자에게 보입니다. 외주·당사별 제한이 필요하다면 금고 그룹 접근제어
  정책을 추가하기 전까지 공용 비밀번호 범위를 운영에서 검토해야 합니다.

가장 중요한 사전 확인 — '미분류' 전체 공개 영향
  · 1.3.1 DB 마이그레이션은 명시 그룹이 없는 기존 업무를 ALL로 바꿉니다.
  · 외주 계정에도 제목·본문·첨부 등 해당 기록이 보일 수 있습니다.
  · 기존 그룹이 지정된 업무는 해당 설정을 그대로 유지합니다.
  · 운영 DB에서 미분류 대상 수와 내용의 민감도를 검토한 뒤 적용하십시오.
  · 사전 점검과 변경 승인 없이 업무 서버에 바로 적용하지 마십시오.

절차
  1) 사용자에게 점검 시간 공지, 작업 중인 Import/Export 작업 종료 확인.
  2) backup.cmd로 DB/첨부 백업 및 별도 보관된 VAULT_KEY 복원 가능 여부 확인.
  3) 이 문서의 기존 안내대로 압축을 푼 뒤 UPDATE.cmd 실행.
  4) 화면에 마이그레이션/앱 시작/DB 응답 확인 표시가 모두 나타나는지 확인.
  5) 로그인한 뒤 /settings, /knowledge, /credentials, /audit, /handovers 확인.
  6) 당사/외주/그룹만 있는 계정별로 인수인계·문서·금고 열람 경계 확인.
  7) 오류가 나면 실패 로그, 백업 위치를 확인하고 복구 절차 진행.

Windows 설치 PC에서 'frontend/src'는 필요하지 않습니다.
수정 화면은 이미 빌드된 frontend/dist를 앱 전용 패치가 교체합니다.
