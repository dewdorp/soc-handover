# 서식 있는 본문(리치 텍스트) — 설계와 근거 (1.4.0)

인수인계 내용 · 댓글 · 운영 지식에 표 · 스크린샷 · 로그 블록 · 링크 · 서식을 넣을 수 있게
한 판의 설계 문서입니다. 무엇을 바꿨는지보다 **왜 이렇게 했는지와, 무엇을 지켰는지**를
적습니다. 시험 결과는 `VERIFICATION_1.4.0.md`, 배포 절차는 `RELEASE_1.4.0.md` 에 있습니다.

---

## 1. 바꾸기 전 구조 분석

| 본문 | 저장 칼럼 | 누가 그 텍스트를 읽는가 |
|---|---|---|
| 인수인계 내용 | `handovers.content` (TEXT) | 목록 미리보기 · 통합 검색 · Excel 내보내기/가져오기 · 버전 스냅숏 · 버전 비교 · 재확인 판정 · 알림 · RAG 조각 |
| 인수인계 댓글 | `handover_comments.body` | 댓글 목록 · 타임라인 · 감사 |
| 운영 지식 | `knowledge_articles.body` + `knowledge_revisions.body` | 검색 · 관련 절차 추천 · 개정 비교 · 복원 |
| 할일 설명 / 댓글 | `tasks.description` / `task_comments.body` | 할일 목록 · 검색 |

- 화면은 모두 `whitespace-pre-wrap` 순수 텍스트였고, 표는 탭/공백으로 흉내 냈습니다.
- 첨부는 `attachments(entity_type, entity_id)` 다형 표 하나로, 다운로드할 때마다
  `_entity()` → 열람 그룹 판정(`group_service.assert_visible`)을 다시 지납니다.
  **관리자도 소속되지 않은 제한 그룹은 읽지 못합니다** — 이 판정식을 그대로 재사용합니다.
- 버전(`handover_versions`)은 `VERSIONED_FIELDS` 의 스냅숏이고, 재확인(re-ack)은
  `REACK_FIELDS` 중 하나가 바뀌면 일어납니다.

여기서 나온 원칙: **기존 텍스트 칼럼의 의미를 바꾸지 않는다.** 검색 · Excel · RAG ·
버전 비교 · 옛 API 가 모두 그 칼럼을 읽고 있으므로, 서식은 옆 칼럼에 따로 둡니다.

## 2. 무엇을 서식 있는 본문으로 바꿨고, 무엇은 그대로인가

| 바꾼 것 (1차) | 바꾼 것 (2차) | 그대로 둔 것 |
|---|---|---|
| 인수인계 내용 | 할일 설명 | 제목 · 비고 · 태그 · 관계사 |
| 인수인계 댓글 | 할일 댓글 | 개인 메모 · 일정 설명 · 근무표 메모 |
| 운영 지식 본문 | | 금고 항목 메모 · 설정 값 · 감사 사유 |

짧은 텍스트는 그대로입니다(요청: "간단한 텍스트가 적합한 항목까지 무조건 리치 텍스트로
변경하지 마라").

## 3. 편집기 선택 — Tiptap 3 (ProseMirror)

| 후보 | 라이선스 | 오프라인 | 표 · 셀 병합 | 판단 |
|---|---|---|---|---|
| **Tiptap 3.35 (ProseMirror)** | MIT | npm 번들 — 외부 호출 없음 | prosemirror-tables (병합 · 열 너비) | **채택** |
| Lexical | MIT | 가능 | 표 플러그인이 아직 병합 · 붙여넣기에서 약함 | 보류 |
| Quill 2 | BSD | 가능 | 표 모듈이 기본 기능 수준 | 탈락 — 표가 핵심 요구 |
| CKEditor 5 | GPL-2.0+ / 상용 | 가능 | 우수 | 탈락 — GPL 또는 상용 계약 필요 |
| TinyMCE 7 | GPL-2.0+ / 상용 | 자체 호스팅 가능 | 우수 | 탈락 — 같은 이유 |
| Markdown + textarea | — | 가능 | 표 작성이 어렵다 | 탈락 — Excel 붙여넣기 · 스크린샷 요구 |

채택 이유

1. **저장 형식이 HTML 이 아니라 문서 구조(JSON)다.** 서버가 허용 목록으로 검사하기 쉽고,
   화면은 그 구조를 React 요소로 직접 그려 `dangerouslySetInnerHTML` 이 필요 없습니다.
2. 표 병합 · 열 너비 · Excel 붙여넣기(HTML 표) 를 ProseMirror 가 정확하게 처리합니다.
3. 모든 패키지가 MIT(`@tiptap/*` 3.35.0, `prosemirror-*`, `linkifyjs`) — 폐쇄망 배포에 제약이 없습니다.
4. 번들에 들어가 CDN · 외부 서비스 호출이 없습니다. 편집기는 **편집할 때만** 따로
   불러옵니다(`RichEditor-*.js` 498KB / gzip 157KB). 첫 화면 묶음은 718KB → 735KB(+17KB, 읽기 화면용).

Tiptap 의 유료 확장(협업 · AI · 클라우드 변환)은 쓰지 않습니다.

## 4. 저장 방식

```
handovers.content       TEXT   ← 서버가 content_doc 에서 다시 뽑은 순수 텍스트 (검색 · Excel · RAG · 비교)
handovers.content_doc   JSON   ← 편집기 문서 구조. NULL = 서식 없는 옛 글
```

같은 짝: `handover_comments.body_doc`, `knowledge_articles.body_doc`,
`knowledge_revisions.body_doc`, `tasks.description_doc`, `task_comments.body_doc`
(PostgreSQL 은 JSONB, SQLite 는 JSON). 마이그레이션 `c3e8a1d74b52`.

- **클라이언트가 보낸 텍스트는 믿지 않습니다.** `*_doc` 을 받으면 텍스트 칼럼은 서버가
  `richdoc.to_text()` 로 다시 만듭니다. 표는 `칸 | 칸 | 칸` 줄로, 그림은 `[그림: 설명]`,
  목록은 `- ` · `1. ` · `[x] ` 로 바뀌어 검색과 Excel 에서 읽힙니다.
- **옛 글은 일괄 변환하지 않습니다.** `*_doc` 이 NULL 이면 텍스트를 줄바꿈 그대로 보여 주고,
  사람이 고칠 때 편집기가 텍스트를 문단으로 읽어 들여 그때 처음 구조가 생깁니다.
  마이그레이션은 칼럼만 더합니다 — 기존 행의 어떤 값도 바꾸지 않습니다.
- **옛 API 클라이언트**: `content` 만 보내 글을 바꾸면 지금처럼 순수 텍스트 글이 됩니다
  (`content_doc` 을 NULL 로). 글은 그대로 두고 다른 필드만 고치면 서식을 지우지 않습니다 —
  옛 클라이언트가 상태만 바꿨는데 표가 사라지면 안 되기 때문입니다. 읽을 때 `content` 는
  여전히 채워져 있습니다.

## 5. 본문 그림

### 5-1. 저장 위치 — 기존 첨부 저장소를 그대로

그림은 Base64 로 본문이나 DB 에 넣지 않습니다. 기존 첨부 폴더와 `attachments` 표를 쓰고,
새 칼럼 `attachments.kind` 로 구분합니다.

| kind | 뜻 | 첨부 탭에 보이는가 | 사람이 지울 수 있는가 |
|---|---|---|---|
| `FILE` (기본, 기존 행 전부) | 일반 첨부 | 보인다 | 지금과 같다 |
| `INLINE` | 본문에 끼운 그림 | 안 보인다 | 본문에서만 뺀다 — 파일은 옛 버전 복원을 위해 남긴다 |

본문에는 `/api/v1/attachments/{id}/inline` 주소만 들어갑니다. 서버 검사는 이 형태가 아닌
그림 주소(외부 주소 · `data:` · `javascript:`)를 모두 거절합니다.

### 5-2. 아직 번호가 없는 새 글 — 초안(DRAFT) → 저장할 때 묶기

1. 붙여넣기 · 끌어 놓기 · 버튼으로 그림을 넣으면 곧바로 `POST /attachments/inline` 으로
   올라가 `entity_type='DRAFT', entity_id=<올린 사람>` 으로 저장됩니다.
   초안 그림은 **올린 본인만** 볼 수 있습니다.
2. 글을 저장하면 서버가 본문의 그림 번호를 하나씩 확인해 그 글에 묶습니다(`bind_inline`).
   - 내 초안 → 이 글에 묶음
   - 이미 이 글의 그림 → 그대로
   - 다른 글의 그림(복사해 붙여 넣은 경우) → **내가 그 글을 볼 수 있을 때만 복사본**을 만들어 묶음
   - 남의 초안 · 볼 수 없는 글의 그림 · 지워진 그림 → 저장 거절
3. 24시간이 지나도 묶이지 않은 초안은 파일까지 지웁니다(그림을 올릴 때 30분에 한 번 정리).
4. 한 사람의 묶이지 않은 초안은 200개 · 300MB 까지, 그림 한 장은 20MB(일반 첨부 상한이 더 작으면 그 값)까지.

### 5-3. 권한 — 글을 그대로 상속

`GET /attachments/{id}/inline` 은 **요청할 때마다** 그 글의 열람 판정을 다시 지납니다.
댓글 그림은 그 인수인계에 묶이므로 인계를 볼 수 있는 사람만 봅니다. 권한을 잃거나 글이
지워지면 다음 요청부터 404 입니다.

응답 머리글: `Cache-Control: no-store, max-age=0` · `Pragma: no-cache` ·
`X-Content-Type-Options: nosniff` · `Content-Security-Policy: default-src 'none'; img-src 'self'; sandbox` ·
`Content-Disposition: inline`. 브라우저 · 프록시 캐시에 남지 않아 권한 변경 뒤 캐시로 보이는 일이 없습니다.

형식은 확장자가 아니라 **파일 앞부분(매직 바이트)** 으로 판정합니다 — PNG · JPEG · GIF · WEBP 만.
SVG(스크립트를 담을 수 있음)는 받지 않습니다. 백신 검사 명령(`ATTACHMENT_SCAN_COMMAND`)이
설정돼 있으면 일반 첨부와 똑같이 검사하고, 위험 판정이면 올리지 않습니다.

화면에 보이는 것은 감사에 남기지 않습니다(인계를 여는 것과 같은 행위). **원본 받기**는
일반 첨부와 같은 `/download` 경로라 `ATTACHMENT_DOWNLOAD` 로 남습니다.

## 6. 재확인(re-ack) 판정 — 사용자 결정 (b)

> 글 · 표 · 그림(과 링크 주소)이 바뀔 때만 재확인. 서식만 바뀌면 재확인하지 않는다.

| 바뀐 것 | 새 버전 | 재확인 |
|---|---|---|
| 글자 · 표 칸 내용 · 목록 항목 · 로그 블록 내용 | 생긴다 | **요청** |
| 그림 추가 · 삭제 · 교체 | 생긴다 | **요청** |
| 링크 주소 | 생긴다 | **요청** |
| 굵게 · 기울임 · 색 · 강조 · 제목 크기 · 그림 너비 · 표 열 너비 | 생긴다 | 하지 않음 |
| 댓글 쓰기 · 고치기 · 지우기 | **생기지 않는다** | **하지 않음** |

구현: `content_doc` 은 버전에 들어가지만 재확인 칼럼이 아닙니다. 순수 텍스트(`content`)가
같고 `richdoc.media_signature()`(그림 번호 · 링크 주소)가 같으면 '내용은 같다'로 봅니다.

## 7. 보안

| 위협 | 막는 곳 |
|---|---|
| 저장형 XSS (`<script>`, `onerror=`, `javascript:` 링크) | 서버 허용 목록 검사(`richdoc.validate`) — 노드 · 표시 · 속성이 목록 밖이면 **거절**(조용히 고치지 않음). 화면은 구조를 React 요소로 그려 문자열이 실행되지 않음 |
| 위험한 링크 | `http:` · `https:` · `mailto:` 만. 링크는 `target=_blank rel="noopener noreferrer nofollow"` 를 화면이 붙임 |
| 외부 그림 · 추적 픽셀 | 그림 주소는 `/api/v1/attachments/{id}/inline` 형태만 |
| 붙여넣기 HTML | 편집기가 `script · style · iframe · object · embed · link · meta` 와 `style · class · on*` 속성, 외부 그림을 제거한 뒤 받음. 서버가 다시 검사 |
| 임의 CSS | 글자색 6 · 강조색 4 고정 팔레트, 그림 너비 25/50/75/100% 만 |
| 거대 문서로 서버 · 화면 마비 | 구조 2MB · 노드 4만 · 깊이 30 · 글자 50만 · 그림 100개 상한. 댓글 · 할일은 텍스트 2만 자 |
| 남의 그룹 그림을 번호로 찌르기 | 매 요청 열람 판정 → 404(존재 여부도 숨김). **관리자도 예외 없음** |
| 남의 초안 훔쳐 쓰기 | 초안은 올린 본인만 보기 · 묶기 가능 |
| 권한 회수 · 삭제 뒤 캐시 | `no-store` · 매 요청 판정 |
| 감사로그 비대 | 본문 구조 대신 요약만 남김: `{"nodes": n, "images": n, "tables": n, "code_blocks": n}`. 그림 데이터는 기록하지 않음 |
| 장비 비밀번호 자동 삽입 | 편집기는 금고와 연결이 없고, 양식 · 템플릿 기능은 비밀번호를 끌어오지 않음 |
| 로그 블록 속 공격 문자열 | 코드 블록은 텍스트로만 그림 — `<script>` 가 글자 그대로 보이고 실행되지 않음. 복사 버튼은 원문 그대로 복사 |

## 8. 화면

- 핵심 도구만 보이고(굵게 · 목록 · 번호 · 체크리스트 · 표 · 그림 · 로그/코드 · 링크 · 되돌리기)
  나머지는 **더 보기**(기울임 · 밑줄 · 취소선 · 글 속 코드 · 제목 · 인용 · 구분선 · 글자색 · 강조).
  모든 버튼에 풍선 도움말(단축키가 있으면 함께, 예: `굵게 (Ctrl+B)`).
- 표 · 그림 · 코드 블록을 누르면 그 자리에 맞는 도구 줄(행/열 추가 · 삭제 · 병합 · 머리글,
  그림 크기 · 설명 · 원본 받기, 코드 종류)이 나옵니다.
- **미리보기**는 읽기 화면과 같은 그리기 코드를 씁니다(보이는 대로 저장됩니다).
- 그림 올리는 중에는 저장 버튼이 잠기고 '그림 올리는 중… (n)' 이 보입니다.
- 고치던 내용이 있는데 창을 닫거나 다른 메뉴로 가면 확인을 묻습니다(새로고침 · 탭 닫기 포함).
- 댓글은 Ctrl+Enter 로 등록. Esc 는 그림 크게 보기만 닫고, 쓰는 중인 인계 창은 닫지 않습니다.
- 좁은 화면에서 표는 가로로 밀어 보고(본문 전체가 밀리지 않음), 긴 로그는 '줄 접기 / 가로로 보기'를 고릅니다.
- **메뉴는 하나도 늘리지 않았습니다.** 모든 기능이 기존 화면 안에 있습니다.

## 9. 호환성

| 기존 기능 | 결과 |
|---|---|
| 서식 없는 옛 글 보기 · 고치기 | 그대로 보이고, 고치면 그때 구조가 생김 |
| 통합 검색 · 목록 미리보기 | 텍스트 칼럼 그대로 — 표 칸 · 그림 설명까지 검색됨 |
| 통계 | 텍스트 칼럼을 쓰지 않음 — 영향 없음 |
| Excel 내보내기 | `content` 텍스트(표는 `a | b` 줄) |
| Excel 가져오기 | 지금처럼 텍스트 글로 들어옴(`content_doc` NULL) |
| 버전 비교 | 텍스트 줄 비교 그대로 + '내용 서식' 줄에 요약(표 n · 그림 n · 로그·코드 n) |
| 버전 복원 | `content` 와 `content_doc` 을 함께 되돌림. 그림 파일은 지우지 않으므로 옛 판의 그림도 보임 |
| 인수 확인 · 재확인 | 6절 규칙 |
| 운영 지식 개정 이력 · 판 비교 · 복원 | 판마다 `body_doc` 을 함께 보관 · 복원 |
| RAG 조각 | 텍스트 칼럼에서 그대로 만듦 |
| 옛 API (`content` / `body` 만 보냄) | 지금처럼 동작 |
