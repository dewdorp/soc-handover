# RAG 바닥 공사 — 사례 데이터 · 접근 계약 · 검증

> 이 문서는 **아직 모델을 붙이지 않은 상태**의 설계다. 폐쇄망이라 외부 API 를 쓸 수 없고,
> 어떤 모델·색인을 들일지는 정해지지 않았다. 지금 정하지 않으면 나중에 바꾸기 어려운 것만
> 못으로 박아 둔다.
>
> 구현: `backend/app/services/rag_service.py` · `backend/app/api/v1/rag.py`
> 시험: `backend/tests/api/test_rag_groundwork.py` (13건)

## 1. 왜 지금 이것만 하는가

색인을 먼저 만들고 권한을 나중에 붙이면, 색인이 **권한을 우회하는 통로**가 된다. 목록에서는
막아 둔 다른 그룹의 업무가 '요약'이라는 이름으로 나오고, 그때는 이미 벡터가 다 만들어져
있어 되돌리기 어렵다. 그래서 순서를 뒤집었다 — 경계를 먼저 박고, 모델은 나중에 끼운다.

## 2. 사례 문서 (case document)

업무 하나를 '검색해서 읽을 수 있는 글' 한 덩이로 접은 것. 색인을 다시 만들더라도 이 모양이
같으면 질의·평가 기준을 다시 쓰지 않아도 된다.

`GET /api/v1/rag/contract` 의 `fields` 가 단일 출처이며, 아래는 그 설명이다.

| 칸 | 형 | 뜻 |
|---|---|---|
| `case_id` | string | `handover:{id}`. 색인 키이자 원문으로 돌아가는 주소 |
| `title` | string | 업무 제목 |
| `body` | string | 내용 + `[비고]` 를 이어 붙인 본문 |
| `company` | string | 관계사 이름 |
| `status` / `priority` | string | 상태 · 중요도 **이름**(코드가 아니라 사람이 쓰는 말) |
| `tags` | string[] | 태그 |
| `registered_date` / `work_date` | date | 등록일 · 수행일 |
| `people` | string[] | 전달자 · 담당자 · 확인자 **이름만**(계정 id 는 싣지 않는다) |
| `attachment_names` | string[] | 첨부 **이름만**. 파일 내용은 넣지 않는다 |
| `visibility` | string | `GROUPS` \| `ALL` |
| `group_ids` | int[] | 이 사례를 볼 수 있는 그룹. **색인에 함께 저장해야 한다** |
| `updated_at` | datetime | 마지막 변경 시각. 재색인 판단 |
| `version_no` | int | 원문의 버전. 요약이 어느 판을 봤는지 남긴다 |

`schema_version` = **1.0**. 모양이 바뀌면 올린다 — 색인을 다시 만들라는 신호다.

## 3. 접근 계약 (access contract)

`GET /api/v1/rag/contract` 가 기계가 읽을 수 있는 형태로 같은 내용을 내려준다.

1. 색인에는 `group_ids` 와 `visibility` 를 **반드시 함께** 저장한다. 질의 시점에 '그 사람이
   지금 속한 그룹'과 맞춰 거르지 않으면 색인이 권한을 우회한다.
2. **권한 판정의 기준은 색인이 아니라 DB 다.** 검색기는 후보를 추린 뒤 반드시 원문을 다시
   읽어(`handover_service.get_or_404`) 그 사람이 볼 수 있는지 확인한다.
3. 사람이 그룹에서 빠지면 **다음 질의부터** 막혀야 한다. 색인을 다시 만들 때까지 기다리는
   구조를 만들지 않는다.
4. 답변에는 근거가 된 `case_id` 를 함께 낸다. 원문으로 돌아갈 수 없는 요약은 내지 않는다.
5. 아래 '넣지 않는 것'은 **어떤 경로로도** 색인에 넣지 않는다.
6. 외부로 나가는 호출을 두지 않는다(폐쇄망). 모델·색인은 모두 같은 서버 안에 둔다.

### 사례를 꺼내는 길은 하나뿐

```
rag_service.iterate_cases()  →  search_service.iterate()  →  handover_repo (열람 그룹 · 삭제 범위)
```

목록 · 검색 · Excel 내보내기가 쓰는 그 함수다. 그래서 **색인 작업을 돌린 계정이 볼 수 있는
것만** 나온다. 색인은 관리자가 아니라 **전용 계정**으로 돌리고, 그 계정이 어느 그룹에
속하는지가 곧 색인의 범위가 된다.

## 4. 색인에 넣지 않는 것

| 자료 | 왜 |
|---|---|
| 개인 메모 (`private_notes`) | 본인만 보는 자리다. 공유 검색·내보내기에서도 빠져 있다 |
| 장비 비밀번호 (`credentials`) | 평문이 색인에 닿으면 금고(AES-256-GCM)의 뜻이 사라진다 |
| 감사로그 (`audit_logs`) | 증적이지 지식이 아니다. 사람 이름과 접속 흔적이 섞인다 |
| 첨부 파일 **내용** | 본문 추출은 별도 결정이 필요하다(지금은 파일 이름만) |
| 지운 업무 | 지운 것이 요약으로 되살아나면 삭제가 삭제가 아니다 |

## 5. 검증 예시

`GET /api/v1/rag/verification-examples`. 모델이 없으므로 **답을 채점하지 않는다** — 경계가
지켜지는지만 본다. 모델을 붙인 뒤 가장 먼저 돌릴 목록이다.

| id | 물어볼 것 | 반드시 지켜져야 할 것 |
|---|---|---|
| `scope-other-group` | 다른 그룹에만 공개된 업무의 제목 | 근거에 그 `case_id` 가 없고 본문도 인용되지 않는다 |
| `scope-revoked` | 그룹에서 뺀 직후 같은 질문 | 다시 색인하지 않아도 그 순간부터 빠진다 |
| `exclude-private-note` | 개인 메모에만 적은 문구 | 아무것도 찾지 못한다 |
| `exclude-credential` | 비밀번호 보관함에 넣은 계정 이름 | 비밀번호도, 그 일부도 나오지 않는다 |
| `exclude-deleted` | 지운 업무의 내용 | 찾지 못한다 |
| `cite-source` | 아무 업무나 요약 요청 | 답에 `case_id` 가 붙고 그 주소로 원문이 열린다 |

위 여섯 가지는 지금도 **코드로 시험**하고 있다(`test_rag_groundwork.py`) — 모델이 없는
단계에서도 '사례를 꺼내는 길'이 경계를 지키는지는 확인할 수 있다.

## 6. 아직 하지 않은 것 (현장 확인 필요)

- 색인 저장소(파일 기반 벡터 색인 vs PostgreSQL 확장) — 설치 PC 의 디스크·메모리 확인 필요
- 한국어 임베딩 품질 평가 기준
- 색인 전용 계정의 그룹 범위를 누가 정하는가(운영 규정)
- 재색인 주기와 `updated_at` 기반 증분 갱신
