### ② 열람 그룹

- `groups` · `user_groups` · `handover_groups` + `handovers.visibility`
- 판정은 **한 함수**(`group_service.visible_clause`)에서 만들고, 질의를 만드는 모든 자리가 그것을 쓴다:
  목록 · 건수 · 패싯 · 상세 · 이력 · 첨부(미리보기·받기) · 댓글 · 연결된 할 일/일정 · 검색 · 알림 ·
  통계 · Excel · **이미 발급된 내려받기 토큰**
- 역할은 판정에 쓰지 않는다. 관리자도 자기가 속한 그룹만 본다
- 볼 수 없는 건은 **404**(403 이면 존재가 새어 나간다)
- 이관: 기존 자료를 전체 공개로 바꾸지 않고 '미분류' 그룹에 넣는다. 관리자가 관계사별로 옮긴다

### ③ 4조 2교대 근무표

- 16일 주기 `DDDD + (N..)×4`, 조마다 주기 위치(0·4·8·12). 날짜별 행을 깔지 않는다
- 야간은 **시작 날짜** 기준(11/05 야간 = 11/05 18:00 ~ 11/06 09:00)
- 주/월 보기 · 내 근무(14일) · 계획과 실제를 같은 줄에(취소선 · `+이름`)
- 1인 대근 · 맞교환(두 줄, 한쪽 취소 시 양쪽) · 결원 · 되돌리기(지우지 않고 취소로 기록)
- 이중 배정 거절: 같은 날 두 근무, 전날 야간 → 다음 날 주간
- 정원 미달은 `3/4 결원 1명` 으로 줄에 남는다
- 인계 상대 추천: 다음 근무의 **실제** 근무자(대근 반영) → 인계 준비의 '실근무자로 채우기'

### ③-2 복수 담당 · CERT 전파 · 분석 의뢰

- 역할 넷: **대표 담당 · 공동 담당 · 필수 인수자 · 참고**. 한 사람은 한 역할만 가지며,
  같은 사람이 두 역할로 들어오면 **강한 쪽**만 남는다(두 줄이 남으면 확인 숫자가 두 번 세어진다)
- 확인(ack) 의무는 역할이 정한다 — **참고는 미확인으로 잡히지 않는다**
- 대표 담당은 목록의 '담당자'(`assignee_id`)와 같은 사람으로 맞춘다
- **CERT 전체 전파**: 누르기 전에 담당 N / 필수 N / 참고 N / 제외 M 을 보여 주고, 누른
  결과가 그 숫자와 같다. 제외는 '손으로 뺀 사람'과 '이미 더 강한 역할'을 나눠 보여 준다
- **전파는 공개 범위를 넓히지 않는다** — 사람을 거는 것이지 글을 여는 것이 아니다.
  그룹 공개는 앞으로 들어올 사람까지 보지만, 전파는 그때 그 사람들만 걸린다
- 전파는 더하기만 한다. 빼는 것은 '담당 · 전파 대상 바꾸기'이고 본문 수정과 같은 자격을 요구한다
- **분석 의뢰 → 접수 → 회신**: 받는 사람은 필수 인수자로 걸리고(접수를 추적할 사람),
  접수 시각부터 응답 시간이 재어진다. 내용 없는 회신은 받지 않는다. 되돌리기는 없다

### ④ 대시보드 · 알림 팝업 · 일정 알림 · 메모 연결

- 대시보드에서 **'시스템 상태 및 구현 현황'을 뺐다**. Phase 목록과 코드 개수는 만드는 쪽이
  보던 것이지 교대할 때 쓰는 것이 아니다. DB 경고 줄은 남겼다(운영 중에 알아야 한다)
- **알림 팝업** 두 겹: 화면 안 팝업(권한 불필요, 항상)과 바탕화면 알림(단추를 눌러 허용하면
  다른 창을 보고 있어도 뜬다). 폐쇄망에서 돈다 — 바깥으로 나가는 통신이 없다
- 띄우는 것은 **화면을 연 뒤에 생긴** 안 읽은 알림뿐. 처음 열 때 쌓여 있던 것은 종의 숫자가 맡는다
- 인계 · 재확인 · 중요 · 근무 변경은 사람이 닫을 때까지 남고, 나머지는 12초 뒤 사라진다

- **교대 마감 점검** 다섯 줄(확인하지 않은 인계 · 보내지 않은 바구니 · 내 담당 미완료 · 지연 ·
  다음 근무 결원). 숫자는 목록과 **같은 조건**으로 세고, 누르면 그 목록이 열린다
- **내 일정** 7일, 반복은 앞 3회차 + 가려진 회차 수. 일정마다 **내 알림**(끄기/시작/10분/30분/직접)
- 알림은 기존 알림함으로 간다(새 통로 없음). 한 회차에 한 번, 2시간 넘게 지난 것은 보내지 않는다
- **메모 → 내 할 일 / 인계 초안**: 고른 글만 넘어가고, 메모로 되돌아오는 링크는 만들지 않는다

### ⑤ RAG 바닥 공사 (모델 없음)

- 사례 문서 구조(`schema_version` 1.0) · 접근 계약 · 넣지 않는 자료 · 검증 예시 6종
- 사례를 꺼내는 길은 하나: `search_service.iterate()` — 목록·검색·Excel 과 같은 함수
- 자세한 내용: [RAG.md](RAG.md)

| **대량 데이터에서의 체감** | 시연 데이터는 10건이다 | 50만 건 DB 에서 그룹 조건이 붙은 목록 첫 페이지 응답 시간 |
| **설치 PC 의 실제 사양에서의 성능** | 이 PC 는 개발 PC(SSD · 충분한 메모리)다 | 설치 PC 에서 목록 첫 페이지 · 검색 응답 시간 |
| **알림 주기** | 이 PC 는 `REMINDER_INTERVAL_MIN=0`(끔)으로 시험했다 | 설치 PC 에서 값이 켜져 있는지, 일정 알림이 실제로 도착하는지 |
| **RAG** | 모델·벡터 DB 를 정하지 않았다 | [RAG.md](RAG.md) §6 |
| **교대 시각의 로그인 상한** | 여기서는 사람이 한 명이다 | 교대 시각에 `로그인이 막힌다`는 말이 나오면 `RATE_LIMIT_LOGIN_PER_5MIN` 을 올린다(SECURITY §8-1) |

## 4. 업그레이드할 때 알아야 할 것

마이그레이션 네 개가 올라간다.

| 리비전 | 내용 | 기존 자료에 생기는 일 |
|---|---|---|
| `c8a2f4e7b015` | 열람 그룹 | **'미분류' 그룹**이 만들어지고, 기존 업무 전부와 기존 사용자 전부가 그 그룹에 들어간다. 보이는 것은 그대로다 |
| `d4b1c7e8a206` | 근무표 | 기본 4조(1~4조)가 만들어진다. **사람은 넣지 않는다** |
| `e5c3a9f1b847` | 일정 알림 | 빈 테이블 |
| `f6d2b8a4c137` | 복수 담당 · 분석 의뢰 | **담당자가 있던 건은 그 사람이 '대표 담당'으로** 들어간다. 보이는 것은 그대로다 |

주의할 것 두 가지.

1. **앞으로 만드는 계정은 그룹에 넣기 전까지 과거 자료를 보지 못한다.** 의도한 동작이다
   (새 사람에게 과거 자료가 자동으로 열리지 않는다). 관리자 → 열람 그룹 → 구성원에서 넣는다.
2. 업그레이드 직후에는 모두가 '미분류' 한 그룹에 있어 **1.2.0 과 똑같이 보인다**. 그룹을 나누는
   것은 관리자가 따로 하는 일이다.
3. 분석 의뢰는 **모든 건이 '의뢰 없음'** 으로 시작한다. 올리자마자 의뢰 중인 건이 생기지 않는다.
